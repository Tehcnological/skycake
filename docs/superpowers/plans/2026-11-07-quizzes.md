# Quizzes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A site hands `mount()` a quiz, or asks for endless practice, and the view runs it: the four question types (tap to find, read the view, where's the airplane, fly the procedure) on the shared question card, questions generated from the FAA data and mixed with written ones, a running score, and a result callback for the site.

**Architecture:** Pure, Node-testable modules hold the logic:
- `airclass.ts`: ground height, the class of airspace at a point, and what that class requires.
- `generate.ts`: the four question generators, seeded, drawing every answer and wrong choice from the data.
- `quiz.ts`: the attempt state, with shuffle, per-attempt drawing and practice.

`quizui.ts` builds the quiz's DOM around the card from the walkthrough plan. `validate.ts` gains `validateQuiz`.

**Tech Stack:** TypeScript 5.9, three.js 0.180.0 (peer), node:test via tsx, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-04-skycake-ux-design.md` (sections "Quizzes", "Embedding", "Accessibility", "Testing", build order steps 3 and 4).

This is plan 3 of 3. It needs the walkthrough plan (`2026-11-07-walkthroughs.md`) done first:
- `Question`, `Answer`, `score`, `questionScene`, `revealScene` (`question.ts`)
- `card()` (`card.ts`)
- `View.tap`, `View.onScreen`, `View.focus`, `View.camera`, `stripPlayback`
- `Options.mode` and `validate.ts`

## Global Constraints

- Everything in the walkthrough plan's Global Constraints applies here too: no em dashes, labels, 44 px, the 76 px phone bar, motion, the caption line, nothing stored, ACS/PTS tags on the site only.
- Generated answers and wrong choices come only from `area.json`, `dem.bin` and the procedure files, never invented. Generated questions carry no explanation; the answer card shows the data instead (for example "Chandler Class D · SFC to 3,000").
- Choices: 2 to 4, distinct. Numbers have a tolerance.
- Airplane questions: altitudes between 500 ft AGL and 17,500 ft MSL. Points within 0.5 NM or 300 ft of a boundary are skipped.
- Class rules for the airplane:
  - B, C or D when inside the area's outline with floor <= ft < ceiling.
  - Otherwise E when inside a surface E area, above 700 ft AGL inside an E700 outline, above 1,200 ft AGL elsewhere, or above 14,500 MSL.
  - Otherwise G.
- What a point requires, for an ordinary airplane with an engine-driven electrical system:
  - An ATC clearance in Class B (14 CFR 91.131(a)).
  - Two-way radio communication in Class C (91.130(c)) and Class D (91.129(c)).
  - An altitude-reporting transponder (91.215(b)) when any of these apply:
    - in Class B or C ((b)(1));
    - inside the Mode C veil, up to 10,000 MSL ((b)(2));
    - above the ceiling of a Class B or C area (surface area or shelf) and within its outline, up to 10,000 MSL ((b)(4));
    - at or above 10,000 MSL, except at or below 2,500 ft AGL ((b)(5)(i)).
- `onResult` is called after each answer and at the end; skycake stores nothing and the site decides what to record.

## Review Focus

- A practice filter that matches nothing (`kinds: ["P"]` in an area with no prohibited areas, or an airport with no procedures): practice says there is nothing to ask and offers Explore, instead of spinning. Pinned in Task 3.
- An area with too few neighbours for 4 distinct choices (one Class D in the area): the question has 2 or 3 choices, never a repeat. Pinned in Task 2.
- A written quiz mixing a find question, a number question and a `generate` item, shuffled: each attempt redraws the generated items and the order changes; the written ones stay identical. Pinned in Task 3.
- Tapping near, not on, a small target: a tap 1.4 NM from a fix counts, 1.6 NM does not. Pinned in the walkthrough plan's Task 3; Task 4 here checks it in a browser.
- An airplane point right at a shelf's floor (the 300 ft rule) or 0.4 NM from its edge: never generated. Pinned in Task 2.
- An airplane at 11,000 MSL over high terrain: a transponder is required unless it is within 2,500 ft of the ground, inside the veil or not. Pinned in Task 1.

### Task 1: Class of airspace at a point

**Files:**
- Create: `src/airclass.ts`, `src/airclass.test.ts`

**Interfaces:**
- Consumes: `AirspaceFile`, `inRing`, `deepest` (`airspace.ts`); `nm` (`cifp.ts`).
- Produces:
  - `export function groundFt(data: AirspaceFile, grid: Int16Array | null, lat: number, lon: number): number`: bilinear over the DEM grid (`nx` by `ny`, row 0 along the north edge, column 0 along the west, over `data.bounds`), as `viewer.ts` samples it; `data.ground` without a grid.
  - `export type Class = { kind: "B" | "C" | "D" | "E" | "G"; area: string | null; veil: boolean; overBC: boolean; agl: number }`. `area` is the id of the B, C, D or surface E area the point is in. `overBC` is true when the point is inside the outline of any B or C piece (surface area or shelf) and at or above that piece's ceiling (91.215(b)(4); corrected during the build, 2026-11-07). `agl` is the height above the ground.
  - `export function classAt(data: AirspaceFile, grid: Int16Array | null, lat: number, lon: number, ft: number): Class`, by the rules in Global Constraints.
  - `export function needs(c: Class, ft: number): { clearance: boolean; radio: boolean; transponder: boolean }`, by the rules in Global Constraints.
  - `export function nearBoundary(data: AirspaceFile, grid: Int16Array | null, lat: number, lon: number, ft: number): boolean`: true within 0.5 NM of any B, C, D, E, E700 or MODEC outline edge. Also true within 300 ft vertically of:
    - the floor or ceiling of an area the point is inside,
    - the E floor that applies (700 or 1,200 AGL),
    - 14,500 or 10,000 MSL,
    - 2,500 AGL, at or above 10,000 MSL.
- `viewer.ts` moves its sampling onto `groundFt`, so the browser and Node agree.

### Task 2: Question generators

**Files:**
- Create: `src/generate.ts`, `src/generate.test.ts`
- Modify: `src/ui.ts` (`Labels.ask`, see below)

**Interfaces:**
- Consumes: `Question` (`question.ts`); `classAt`, `needs`, `nearBoundary`, `groundFt` (Task 1); `Procedure`, `Fix` (`procedure.ts`).
- Produces:
  - `export type Rng = () => number` and `export function seeded(seed: number): Rng` (mulberry32).
  - `export type QuestionType = "find" | "read" | "airplane" | "procedure"`.
  - `export type Gen = { data: AirspaceFile; grid: Int16Array | null; procedures: Procedure[]; ask: Labels["ask"]; kinds?: Kind[]; airports?: string[] }`.
  - `export function generate(type: QuestionType, g: Gen, rng: Rng): (Question & { facts: string | null }) | null`: null when the filters leave nothing to ask. `facts` is the answer card's data line.
  - `Labels.ask` holds the generated prompts, placeholders for Chris:

    ```ts
    {
      findArea: (name) => `Tap the ${name}`,
      findFix: (fix) => `Tap ${fix}`,
      floor: "What is the floor of the highlighted airspace?",
      ceiling: "What is its ceiling?",
      cls: "What class is the highlighted airspace?",
      airplaneClass: "What airspace is the airplane in?",
      clearance: "Does the pilot need an ATC clearance here?",
      radio: "Is two-way radio communication required here?",
      transponder: "Is an altitude-reporting transponder required here?",
      yes: "Yes",
      no: "No",
      altAt: (fix) => `What altitude is charted at ${fix}?`,
      after: (fix) => `Which fix comes after ${fix}?`,
      faf: "Which fix is the final approach fix?",
      missed: "Which fix starts the missed approach?",
    }
    ```

What each type generates:
- **find:** an area of an allowed kind, raised kinds none, camera `"top"`, `answer: { area }`. When `g.procedures` is not empty, also a fix on one of them, with the scene showing that procedure and `answer: { fix }`.
- **read:**
  - The floor or ceiling of one area as choices. The area is highlighted flat on the chart, and the camera moves top-down to it so the chart can be read. Nothing locks the camera. The wrong choices are the distinct floors or ceilings of the nearest areas of the same kind, by distance between `deepest()` points.
  - Or its class, with the other classes present in the area as the wrong choices.
  - Values are shown with `hundreds()` as on the chart, or "SFC".
- **airplane:** a random point and altitude inside the bounds and the limits, redrawn up to 200 times until `nearBoundary` is false. The scene shows the airplane at its altitude, nothing raised, with the camera moved top-down over it (`questionScene`) so the sectional can be read. Then either its class (choices: the class and up to 3 other classes, distinct) or one of the three `needs` questions (Yes/No).
- **procedure:** among the procedures in `g.procedures` (the `airports` filter, or all):
  - the charted altitude (`alt`) at a fix that has one, with wrong choices from the other fixes' altitudes on the same procedure;
  - the fix after a given fix in the flight line;
  - the FAF;
  - the first fix of the missed approach.

  The scene shows only that procedure, framed. A procedure without the needed fixes is skipped.

```ts
test("filters: kinds and airports are respected; nothing left gives null", () => {

  if (data.areas.some((a) => a.kind === "P")) assert.equal(data.areas.find((a) => "area" in (p as any).answer && a.id === (p as any).answer.area)!.kind, "P");
  else assert.equal(p, null);

test("same seed, same questions", () => assert.deepEqual(generate("read", g, seeded(7)), generate("read", g, seeded(7))));
```

### Task 3: Quiz attempts and practice (pure)

**Files:**
- Create: `src/quiz.ts`, `src/quiz.test.ts`

**Interfaces:**
- Consumes: `Question`; `Rng`, `QuestionType` (Task 2).
- Produces:
  - `export type Generate = { generate: QuestionType; count: number; kinds?: Kind[]; airports?: string[] }`.
  - `export type Quiz = { id: string; title: string; area: string; items: (Question | Generate)[]; shuffle?: boolean }`.
  - `export type Item = { q: Question; key: string; facts: string | null }`, where `key` is the question's `id`, or `generate:<type>:<n>` for drawn ones.
  - `export type Attempt = { items: Item[]; i: number; right: number; answered: number; done: boolean; practice: boolean }`.
  - `export type Make = (g: Generate) => (Question & { facts: string | null }) | null`.
  - `export function attempt(quiz: Quiz, make: Make, rng: Rng): Attempt`.
  - `export function practice(make: Make, types: QuestionType[], filters: { kinds?: Kind[]; airports?: string[] }, rng: Rng): Attempt | null`. It returns null when no type can make a question.
  - `export function answer(a: Attempt, right: boolean): Attempt` and `export function advance(a: Attempt, make: Make, rng: Rng): Attempt`. In practice, `advance` appends a freshly made question of a random allowed type.
  - `export type QuizResult = { quiz: string; item: string; right: boolean; ms: number } | { quiz: string; end: true; right: number; total: number }`.

- [ ] **Step 1: Write the failing tests** in `src/quiz.test.ts`, with a stub `make` that counts calls and returns numbered read questions:

```ts
test("written items stay; generated items are drawn fresh each attempt", () => {
  const quiz = { id: "q", title: "", area: "phoenix", items: [written1, { generate: "read", count: 2 }, written2] };
  const a = attempt(quiz, make, seeded(1)), b = attempt(quiz, make, seeded(1));
  assert.deepEqual(a.items.map((x) => x.key), ["w1", "generate:read:0", "generate:read:1", "w2"]);
  assert.notDeepEqual(a.items[1].q, b.items[1].q); // make was called again
});
test("shuffle reorders with the rng, keeping every item", () => {
  const a = attempt({ ...quiz, shuffle: true }, make, seeded(3));
  assert.deepEqual(a.items.map((x) => x.key).sort(), ["generate:read:0", "generate:read:1", "w1", "w2"]);
  assert.notDeepEqual(a.items.map((x) => x.key), ["w1", "generate:read:0", "generate:read:1", "w2"]);
});
test("scoring and the end", () => {
  let a = attempt(quiz, make, seeded(1));
  for (const r of [true, false, true, true]) a = advance(answer(a, r), make, seeded(1));
  assert.deepEqual([a.right, a.answered, a.done], [3, 4, true]);
});
test("practice never ends, and is null when nothing can be asked", () => {
  let a = practice(make, ["read"], {}, seeded(1))!;
  for (let i = 0; i < 50; i++) a = advance(answer(a, true), make, seeded(i));
  assert.equal(a.done, false);
  assert.equal(practice(() => null, ["find"], { kinds: ["P"] }, seeded(1)), null);
});
```
